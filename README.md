## Задача 1. Распил брусьев (№ 36)

### 1. Ссылка на задачу
* **Платформа:** Яндекс CodeRun
* **Задача:** [36. «Распил брусьев»](https://coderun.yandex.ru/problem/sawing-beams)  

---

### 2. Исходный код решения на Python (PEP-8)

```python
import sys


def find_min_cutting_cost(length: int, cuts: list[int]) -> int:
    """Считает минимальную суммарную стоимость распила бруса на части.

    :param length: Полная длина исходного бруса L.
    :param cuts: Координаты точек распила по возрастанию.
    :return: Минимальная итоговая стоимость заказа.
    """
    # Добавляем координаты краев (0 и L), чтобы однозначно задавать любой кусок
    points = [0] + cuts + [length]
    num_points = len(points)

    # dp[i][j] — минимальная стоимость распила куска от points[i] до points[j]
    dp = [[0] * num_points for _ in range(num_points)]

    # segment_len — длина отрезка в элементарных сегментах (j - i)
    # Считаем снизу вверх: от коротких отрезков к длинным
    for segment_len in range(2, num_points):
        for i in range(num_points - segment_len):
            j = i + segment_len
            current_cut_cost = points[j] - points[i]

            # Ищем, в какой внутренней точке k выгоднее сделать первый распил
            min_sub_cost = float('inf')
            for k in range(i + 1, j):
                total_cost = dp[i][k] + dp[k][j]
                if total_cost < min_sub_cost:
                    min_sub_cost = total_cost

            dp[i][j] = current_cut_cost + min_sub_cost

    # В ячейке dp[0][num_points - 1] лежит ответ для всего исходного бруса
    return dp[0][num_points - 1]


def main() -> None:
    """Считывает входные данные и выводит ответ."""
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    length = int(input_data[0])
    num_cuts = int(input_data[1])
    cuts = [int(x) for x in input_data[2:2 + num_cuts]]

    result = find_min_cutting_cost(length, cuts)
    print(result)


if __name__ == '__main__':
    main()
```

---

### 3. Пояснение: подробное описание хода решения

На первый взгляд задача кажется запутанной: каждый распил делит брус, длины последующих кусков меняются, и кажется, что нужно перебирать все возможные порядки распилов. Но задачу можно свести к аккуратному динамическому программированию по подотрезкам:

1. **Добавляем концы бруса в список точек:**  
   Сам брус начинается в координате `0` и заканчивается в `L`. Если склеить их с метками распилов, получим отсортированный массив:  
   `points = [0, C1, C2, ..., Cn, L]`.  
   Теперь края абсолютно любого куска бруса, который вообще может возникнуть в процессе работы, задаются просто парой индексов `(i, j)`, а длина этого куска всегда равна `points[j] - points[i]`.

2. **Формулируем подзадачу (состояние ДП):**  
   Пусть `dp[i][j]` — минимальная стоимость распила куска бруса от отметки `points[i]` до отметки `points[j]` по всем точкам, лежащим строго между ними.

3. **Базовый случай:**  
   Если точки идут подряд (`j = i + 1`), между ними нет никаких промежуточных меток для распила. Пилить ничего не нужно, стоимость равна нулю:  
   `dp[i][i + 1] = 0`.

4. **Переход динамики:**  
   Если внутри отрезка от `i` до `j` есть хотя бы одна точка распила, нам нужно выбрать: **какой из распилов сделать первым на этом куске?**  
   Допустим, первым мы распилили в точке `k` (где `i < k < j`):
   * За сам этот распил мы заплатим текущую длину куска: `points[j] - points[i]`.
   * Брус распадается на два независимых куска: левый (от `i` до `k`) и правый (от `k` до `j`).
   * Дальше они распиливаются автономно друг от друга, поэтому их суммарная минимальная стоимость составит `dp[i][k] + dp[k][j]`.
   
   Мы перебираем все возможные варианты первого распила `k` и выбираем самый дешевый:  
   `dp[i][j] = (points[j] - points[i]) + min(dp[i][k] + dp[k][j])` для всех `i < k < j`.

5. **Порядок обхода:**  
   Чтобы значение `dp[i][j]` посчиталось корректно, мы уже должны знать ответы для более коротких отрезков `dp[i][k]` и `dp[k][j]`. Поэтому вычисления идут по возрастанию длины отрезка `segment_len` (`j - i`) от 2 до полной длины.  
   Итоговый ответ лежит в `dp[0][len(points) - 1]`.

---

### 4. Обоснование выбора алгоритма и структур данных

* **Почему динамическое программирование, а не жадный алгоритм?**  
  Жадные подходы (например, всегда резать ближе к середине или начинать с наименьших кусков) не работают: локально выгодный распил может оставить огромный кусок на потом, из-за чего итоговая сумма только вырастет.  
  Полный перебор всех вариантов дал бы факториальную сложность `O(N!)`. При `N = 100` вариантов порядка `100! ≈ 9.3 × 10^157`, программа бы зависла навсегда.  
  ДП идеально подходит, так как задача обладает оптимальной подструктурой и перекрывающимися подзадачами: мы сохраняем результат для каждого отрезка и не считаем его заново.

* **Почему выбрана матрица (список списков), а не словарь?**  
  * Массив `points` — это обычный `list`, где доступ к координатам по индексу занимает `O(1)`.
  * Для таблицы состояний `dp` используется вложенный список `list[list]` фиксированного размера `(N + 2) × (N + 2)`. Поскольку мы заполняем практически все ячейки таблицы, список списков гораздо быстрее словаря `dict` с ключами-кортежами `(i, j)`, так как не тратит процессорное время на вычисление хэшей и коллизии.

---

### 5. Анализ сложности

* **Временная сложность (Time Complexity):** `O(N^3)`  
  В алгоритме три вложенных цикла: внешний — по длине отрезка, средний — по левой границе `i`, внутренний — поиск точки `k`.  
  Общее число элементарных шагов внутреннего цикла равно:  
  `(N + 2) × (N + 1) × N / 6 ≈ N^3 / 6`.  
  При максимальном `N = 100` число итераций составляет около 171 700. На Python это выполняется за ≈ 0.02 секунды (при лимите в 1–2 с).
* **Пространственная сложность (Space Complexity):** `O(N^2)`  
  Память выделяется под список `points` длины `N + 2` и матрицу `dp` размера `(N + 2) × (N + 2)`. При `N = 100` таблица состоит из `102 × 102 ≈ 10 000` чисел, что занимает менее 1 МБ памяти.

## Задача 2. Узник замка Иф (№ 58)

### 1. Ссылка на задачу
* **Платформа:** Яндекс CodeRun
* **Задача:** [58. «Узник замка Иф»](https://coderun.yandex.ru/problem/prisoner-of-if-castle)  

---

### 2. Исходный код решения на Python (PEP-8)

```python
import sys


def can_brick_pass(brick_dims: list[int], hole_dims: list[int]) -> bool:
    """Проверяет, пролезет ли кирпич в прямоугольное отверстие.

    :param brick_dims: Размеры кирпича [A, B, C].
    :param hole_dims: Размеры отверстия [D, E].
    :return: True, если кирпич пролезет хотя бы одной гранью, иначе False.
    """
    brick_sorted = sorted(brick_dims)
    hole_sorted = sorted(hole_dims)

    # Проверяем, помещаются ли две наименьшие стороны кирпича в отверстие
    return (
        brick_sorted[0] <= hole_sorted[0]
        and brick_sorted[1] <= hole_sorted[1]
    )


def main() -> None:
    """Считывает входные данные и выводит результат проверки."""
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    brick_dims = [int(x) for x in input_data[:3]]
    hole_dims = [int(x) for x in input_data[3:5]]

    if can_brick_pass(brick_dims, hole_dims):
        print("YES")
    else:
        print("NO")


if __name__ == "__main__":
    main()
```

---

### 3. Пояснение: подробное описание хода решения

Первая мысль при чтении условия — выписать все возможные положения кирпича. У кирпича 3 грани (размерами `A × B`, `A × C` и `B × C`), и каждую грань в отверстие `D × E` можно повернуть двумя способами. Получилось бы громоздкое условие из 6 вариантов через `or`, где легко ошибиться.

Но здесь есть простое ключевое наблюдение:

1. **Какая грань имеет больше всего шансов пролезть?**  
   Самая маленькая по габаритам. Если кирпич в принципе может пройти в отверстие, то его **наименьшая грань гарантированно пролезет**. Если же даже наименьшая грань не проходит, то остальные грани тем более больше отверстия и кирпич точно застрянет.

2. **Как найти наименьшую грань?**  
   Достаточно отсортировать измерения кирпича по возрастанию:  
   `b1 ≤ b2 ≤ b3`.  
   Две самые короткие стороны — это `b1` и `b2`. Значит, грань с размерами `b1 × b2` гарантированно наименьшая.

3. **С чем сравнивать?**  
   Отверстие тоже можно поворачивать, поэтому сортируем и его стороны:  
   `h1 ≤ h2`, где `h1` — меньшая сторона отверстия, а `h2` — большая.

4. **Финальная проверка:**  
   Теперь просто прикладываем меньшую сторону кирпича к меньшей стороне отверстия, а большую — к большей:  
   `b1 <= h1 and b2 <= h2`.  
   Если условие истинно — выводим `YES`, иначе `NO`.

---

### 4. Обоснование выбора алгоритма и структур данных

* **Почему такой алгоритм?**  
  Вместо нагромождения условий `if ... or ...` используется сортировка малых списков и сравнение по инварианту. Это делает код максимально лаконичным, легко читаемым и исключает человеческий фактор при переборе всех комбинаций поворота кирпича.
  
* **Почему выбраны обычные списки (`list`)?**  
  На входе всего 5 чисел: 3 для кирпича и 2 для отверстия. Обычный список в Python создается мгновенно, а функция `sorted()` для 2–3 элементов выполняется за считанные процессорные такты. Сложные структуры вроде `dict` или `set` здесь избыточны.

---

### 5. Анализ сложности

* **Временная сложность (Time Complexity):** `O(1)`  
  Чтение 5 чисел, сортировка массивов из 3 и 2 элементов, а также проверка двух неравенств занимают фиксированное количество операций, не зависящее от величины самих чисел. Программа выполняется мгновенно (доли миллисекунды).
* **Пространственная сложность (Space Complexity):** `O(1)`  
  Используются всего два небольших списка фиксированной длины (3 и 2 элемента). Потребление памяти константно и составляет несколько байт.
