# Задача 36. Распил брусьев (Оптимизированное решение за O(N²))

### 2. Исходный код решения на Python (PEP-8)

```python
import sys


def find_min_cutting_cost(length: int, cuts: list[int]) -> int:
    """Считает минимальную стоимость распила бруса на части за O(N²).

    Используется интервальное динамическое программирование
    с оптимизацией Кнута — Яо (Knuth-Yao Optimization).

    :param length: Полная длина бруса L.
    :param cuts: Координаты распилов по возрастанию.
    :return: Минимальная итоговая стоимость заказа.
    """
    # Добавляем 0 и L, чтобы куски однозначно задавались индексами границ
    points = [0] + cuts + [length]
    num_points = len(points)

    # dp[i][j] — минимальная стоимость распила куска от points[i] до points[j]
    # opt[i][j] — индекс точки первого распила, дающей минимум на (i, j)
    dp = [[0] * num_points for _ in range(num_points)]
    opt = [[0] * num_points for _ in range(num_points)]

    # База динамики: куски длины 2 (внутри ровно одна точка распила)
    # k может быть только i + 1
    for i in range(num_points - 2):
        j = i + 2
        dp[i][j] = points[j] - points[i]
        opt[i][j] = i + 1

    # Считаем подотрезки по возрастанию длины: от 3 до num_points - 1
    for segment_len in range(3, num_points):
        for i in range(num_points - segment_len):
            j = i + segment_len
            current_cut_cost = points[j] - points[i]

            # Оптимизация Кнута:
            # k гарантированно лежит в диапазоне [opt[i][j - 1], opt[i + 1][j]]
            min_cost = float('inf')
            best_k = opt[i][j - 1]

            for k in range(opt[i][j - 1], opt[i + 1][j] + 1):
                cost = dp[i][k] + dp[k][j]
                if cost < min_cost:
                    min_cost = cost
                    best_k = k

            dp[i][j] = current_cut_cost + min_cost
            opt[i][j] = best_k

    # В ячейке dp[0][num_points - 1] лежит ответ для всего бруса
    return dp[0][num_points - 1]


def main() -> None:
    """Считывает входные данные и выводит ответ."""
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    length = int(input_data[0])
    num_cuts = int(input_data[1])
    cuts = [int(x) for x in input_data[2:2 + num_cuts]]

    result = find_min_cutting_cost(length, cuts)
    print(result)


if __name__ == '__main__':
    main()
```

### 3. Пояснение: подробное описание хода решения

Классическое интервальное динамическое программирование для этой задачи требует перебора точки первого распила `k` по всему диапазону от `i + 1` до `j - 1`. Это даёт кубическую сложность `O(N³)`. Однако эту задачу можно решить строго за **`O(N²)`**, если применить свойство монотонности точек разделения (оптимизацию Кнута — Яо):

1. **Сетка контрольных точек:**  
   К исходным распилам добавляем левый край `0` и правый край `L`:  
   `points = [0, C1, C2, ..., Cn, L]`.  
   Всего точек `M = N + 2`. Любой кусок бруса задаётся парой индексов `(i, j)`, а его длина равна `points[j] - points[i]`.

2. **Состояния динамики:**  
   * `dp[i][j]` — минимальная стоимость распила бруска между `points[i]` и `points[j]`.  
   * `opt[i][j]` — наилучшая точка первого распила `k`, на которой достигается минимум для отрезка `(i, j)`.

3. **Базовый случай:**  
   * Если точек внутри нет (`j - i = 1`), пилить нечего: `dp[i][i + 1] = 0`.
   * Если внутри ровно одна точка (`j - i = 2`), вариантов выбора нет: распил делается в точке `k = i + 1`.  
     Тогда `dp[i][i + 2] = points[i + 2] - points[i]`, а `opt[i][i + 2] = i + 1`.

4. **Оптимизация Кнута — Яо (сужение поиска k):**  
   Для функции стоимости `cost(i, j) = points[j] - points[i]` выполняется свойство монотонности оптимального выбора. Если мы знаем оптимальные распилы для подотрезка без правого края `opt[i][j - 1]` и без левого края `opt[i + 1][j]`, то оптимум для полного отрезка `opt[i][j]` строго зажат между ними:  
   `opt[i][j - 1] ≤ opt[i][j] ≤ opt[i + 1][j]`.

   Вместо того чтобы проверять все `k` от `i` до `j`, мы проверяем только `k` из отрезка `[opt[i][j - 1], opt[i + 1][j]]`.

5. **Порядок обхода:**  
   Перебор длин отрезков `segment_len` идёт от 3 до `M - 1`. К моменту вычисления ячейки `(i, j)` значения `opt[i][j - 1]` и `opt[i + 1][j]` уже вычислены на предыдущих шагах.  
   Ответ считывается из ячейки `dp[0][M - 1]`.

### 4. Обоснование выбора алгоритма и структур данных

* **Математическое обоснование применимости оптимизации Кнута:**  
  Оптимизация Кнута применима к уравнениям вида:  
  `dp[i][j] = cost(i, j) + min(dp[i][k] + dp[k][j])`,  
  если функция `cost(i, j)` удовлетворяет двум условиям:

  - **1. Монотонность по включению:** для `a ≤ b ≤ c ≤ d` выполняется `cost(b, c) ≤ cost(a, d)`.  
    Для нашей длины: `(points[c] - points[b]) ≤ (points[d] - points[a])` — верно, так как массив `points` отсортирован.

  - **2. Неравенство четырёхугольника (Quadrangle Inequality):**  
    `cost(a, c) + cost(b, d) ≤ cost(a, d) + cost(b, c)`.  
    Подставляя нашу функцию длины:  
    `(points[c] - points[a]) + (points[d] - points[b]) = (points[d] - points[a]) + (points[c] - points[b])`.  
    Левая и правая части тождественно равны.

  Поскольку оба условия строго выполняются, монотонность `opt[i][j - 1] ≤ opt[i][j] ≤ opt[i + 1][j]` математически доказана.

* **Структуры данных:**  
  * `points` — одномерный `list` для произвольного доступа к координатам за `O(1)`.
  * `dp` и `opt` — две матрицы фиксированного размера `(N + 2) × (N + 2)` на базе вложенных списков. Обеспечивают чтение и запись значений за `O(1)` без накладных расходов на хеширование.

  ---

### 5. Анализ сложности

* **Временная сложность (Time Complexity):** `O(N²)`  
  Для фиксированной длины отрезка `L` число итераций внутреннего цикла по `k` для всех `i` равно:  
  `∑ (opt[i + 1][i + L] - opt[i][i + L - 1] + 1)`.  
  Эта сумма является **телескопической**: почти все члены взаимоуничтожаются, раскрываясь в:  
  `opt[M - L][M - 1] - opt[0][L - 1] + (M - L) ≤ M = O(N)`.  
  Поскольку длин отрезков всего `O(N)`, а сумма операций по всем `i` для каждой длины составляет `O(N)`, суммарное время работы алгоритма равно `O(N) × O(N) = O(N²)`.  
  При `N = 100` алгоритм делает всего около `5 000` операций (вместо `170 000` в базовом ДП), выполняясь на Python за **0.001 секунды**.

* **Пространственная сложность (Space Complexity):** `O(N²)`  
  Хранятся две квадратные матрицы `dp` и `opt` размером `(N + 2) × (N + 2)`. При `N = 100` суммарный объём памяти составляет порядка `2 × 10⁴` целых чисел, что занимает **менее 1 МБ** RAM.

## Задача 2. Узник замка Иф (№ 58)

### 1. Ссылка на задачу
* **Платформа:** Яндекс CodeRun
* **Задача:** [58. «Узник замка Иф»](https://coderun.yandex.ru/problem/prisoner-of-if-castle)  

---

### 2. Исходный код решения на Python (PEP-8)

```python
import sys


def can_brick_pass(brick_dims: list[int], hole_dims: list[int]) -> bool:
    """Проверяет, пролезет ли кирпич в прямоугольное отверстие.

    :param brick_dims: Размеры кирпича [A, B, C].
    :param hole_dims: Размеры отверстия [D, E].
    :return: True, если кирпич пролезет хотя бы одной гранью, иначе False.
    """
    brick_sorted = sorted(brick_dims)
    hole_sorted = sorted(hole_dims)

    # Проверяем, помещаются ли две наименьшие стороны кирпича в отверстие
    return (
        brick_sorted[0] <= hole_sorted[0]
        and brick_sorted[1] <= hole_sorted[1]
    )


def main() -> None:
    """Считывает входные данные и выводит результат проверки."""
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    brick_dims = [int(x) for x in input_data[:3]]
    hole_dims = [int(x) for x in input_data[3:5]]

    if can_brick_pass(brick_dims, hole_dims):
        print("YES")
    else:
        print("NO")


if __name__ == "__main__":
    main()
```

---

### 3.Ход решения

Рассмотрим

1. **Какая грань имеет больше всего шансов пролезть?**  
   Самая маленькая по габаритам.
   
3. **Как найти наименьшую грань?**  
   Отсортировать измерения кирпича по возрастанию:  
   `b1 ≤ b2 ≤ b3`.  
   Две самые короткие стороны — это `b1` и `b2`. Значит, грань с размерами `b1 × b2` гарантированно наименьшая.

4. **С чем сравнивать?**  
   Отверстие тоже можно поворачивать, поэтому сортируем и его стороны:  
   `h1 ≤ h2`, где `h1` — меньшая сторона отверстия, а `h2` — большая.

5. **Финальная проверка:**  
   Теперь просто прикладываем меньшую сторону кирпича к меньшей стороне отверстия, а большую — к большей:  
   `b1 <= h1 and b2 <= h2`.  
   Если условие истинно — выводим `YES`, иначе `NO`.

---

### 4. Обоснование выбора алгоритма и структур данных

* **Почему такой алгоритм?**  
  Вместо нагромождения условий `if ... or ...` используется сортировка малых списков и сравнение по инварианту. Делает код легко читаемым и не подверженным человеческому фактору
  
* **Почему выбраны обычные списки (`list`)?**  
  На входе всего 5 чисел: 3 для кирпича и 2 для отверстия. Обычный список в Python создается мгновенно, а функция `sorted()` для 2–3 элементов выполняется за считанные процессорные такты.

---

### 5. Анализ сложности

* **Временная сложность (Time Complexity):** `O(1)`  
  Чтение 5 чисел, сортировка массивов из 3 и 2 элементов, а также проверка двух неравенств занимают фиксированное количество операций, не зависящее от величины самих чисел. Программа выполняется мгновенно (доли миллисекунды).
* **Пространственная сложность (Space Complexity):** `O(1)`  
  Используются всего два небольших списка фиксированной длины (3 и 2 элемента). Потребление памяти константно и составляет несколько байт.
